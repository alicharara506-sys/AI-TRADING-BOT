## Reading these numbers

- **Event Bus.** Dispatch is O(subscriber count) per `publish()` call --
  throughput scales down roughly linearly as the fan-out grows (1M/sec at 1
  subscriber vs ~32K/sec at 100), which is the expected cost of the
  typed-dispatch design, not a bug. The concurrent-publisher run
  (50 coroutines interleaved via `asyncio.gather`) hits the same ~1M/sec
  ceiling as the single-publisher case with one subscriber, confirming
  `asyncio`'s cooperative scheduling doesn't add measurable overhead beyond
  the handler dispatch cost itself.
- **Backtest engine.** ~132K bars/sec end-to-end through the full wired
  pipeline (tick -> bar -> strategy -> risk gate -> sizing -> execution ->
  fill), driving a real `SmaCrossoverStrategy` against a 20,000-bar
  synthetic random walk. A full year of M1 bars for one symbol
  (~370,000 bars) backtests in well under 3 seconds.
- **Signal Fusion.** ~440 evaluations/sec with the full six-module quant
  roster (ADF mean-reversion, Fibonacci confluence, Engulfing pattern,
  BOS/CHOCH market structure, OBV, ATR breakout) re-evaluating a 100-bar
  rolling window from scratch on every call -- no incremental/cached state
  between evaluations. That's the honest cost of independence between
  modules (each recomputes its own indicators over the full window); a
  live strategy evaluating on bar close, not per-tick, has several orders
  of magnitude of headroom against this number.

## No backpressure test

The plan called for a "backpressure under sustained load" case, but the
Event Bus's design makes one meaningless: `publish()` synchronously awaits
every subscriber before returning, so there is no internal queue that can
overflow -- a producer publishing faster than consumers can process is
mechanically impossible, because `publish()` itself won't return until
each handler has run. The fan-out benchmarks above are the actual
throughput ceiling; there is no separate backpressure regime to
characterize.
